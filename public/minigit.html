Overview:

It's a simplified Git-like version control system built in C++. It allows users to track versions of files, make commits, manage branches, perform merges, and compare commits. All via command-line interaction and local file system operations.

Technology Stack:

  • Language: C++
  • CLI
  • Hashing: Custom hash function
  • Persistence: Store commit metadata and file blobs in local file system

Features:

  • init - Initialize a MiniGit repository
  • add "filename" - Stage a file for commit
  • commit -m "message" - Save staged changes with a message
  • log - View commit history
  • branch "branchname" - Create a new branch
  • checkout "branch/commit" - Switch to another branch or commit
  • merge "branch" - Merge a branch into the current branch
  • diff "commit1" "commit2" - Show differences between two commits

Development:

It was developed as a group project in Addis Ababa University to help better understand how real-world systems (like Git) are underpinned by DSA principles such as hashing, trees, DAGs, and file diffing.

In init, I created necessary directories like .minigit/objects and .minigit/commits, and initialized files like HEAD.txt, branches.txt, and index.txt. In add, I read the file content, generated a custom hash using std::hash, saved the content into the objects/ folder, and recorded the filename-hash pair in index.txt.

Each commit stores metadata (message, timestamp, parent, branch) and the list of staged files (filename:hash). Commits are saved in the commits/ folder using a unique hash. The system uses a simple DAG by storing the parent hash in each commit file, allowing us to trace history and support branches and merges.

I divided the tasks based on strengths—for example, I handled init , add, and overall structure. I maintained regular syncs, reviewed code, and managed integration to ensure smooth collaboration and feature alignment.

We used a hash map to track file versions (filename -> hash), a DAG structure for commit history, and applied hashing to detect content changes. The project helped us understand Git internals like staging, versioning, branches, and merges using minimal yet effective data structures.
